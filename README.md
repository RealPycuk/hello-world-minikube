# Развертывание веб-приложения в кластере Minikube (Kubernetes)

Решение практического тестового задания на позицию стажера DevOps-инженера. 

## Структура проекта
* `app.py` — веб-приложение "Hello World" на FastAPI (работает на порту 32777).
* `Dockerfile` — инструкция для сборки оптимизированного Docker-образа приложения.
* `requirements.txt` — список зависимостей проекта.
* `k8s-manifests.yaml` — объединенный манифест Kubernetes (Deployment на 2 реплики и Service типа ClusterIP).
* `scheme.png` — схема организации контейнеров и сервисов.

## Ход выполнения работы

1. **Разработка и контейнеризация:**
   Приложение написано на Python с использованием фреймворка FastAPI. Сборка Docker-образа оптимизирована с точки зрения кэширования слоев (сначала копируются зависимости `requirements.txt` и запускается установка, затем переносится исходный код). Образ собран и опубликован на Docker Hub: `rusyajez/hello-fastapi:v1.0`.

2. **Запуск локального кластера:**
   Кластер развернут локально с использованием Minikube и докер-драйвера:
   ```bash
   ./minikube.exe start --driver=docker
   ```

3. **Деплой манифестов:**
   Конфигурация Deployment (2 реплики пода) и Service (ClusterIP) успешно применена в пространство имен `default`:
   ```bash
   ./minikube.exe kubectl -- apply -f k8s-manifests.yaml
   ```

4. **Проверка доступности и балансировки:**
   Для проверки распределения трафика был поднят сетевой туннель `kube-proxy` через Minikube Service:
   ```bash
   ./minikube.exe service hello-world-service
   ```
   При открытии адреса туннеля в разных браузерах (или в режиме инкогнито) значение поля `"handled_by_pod"` динамически меняется между двумя запущенными подами. Это подтверждает корректную работу встроенного балансировщика Kubernetes Service.
